# ATML PA3 — Fine-tuning, Visual Grounding, and Test-Time Compute

Code, configurations, split/example IDs and machine-readable results for the three PA3 tasks.
Every reported number is produced by a script below and saved under `results/`.

| Task | Where it runs | Entry point |
|---|---|---|
| 1. LLM fine-tuning (Qwen3-0.6B, MetaMathQA) | Kaggle, GPU T4 ×2 | `task1_finetune/atml-pa3-task1.ipynb` → `python -m task1_finetune.run_all` |
| 2. SigLIP–Qwen VLM and visual grounding | Kaggle or Colab, one T4 | `task2_vlm/atml-pa3-task2.ipynb` → `python -m task2_vlm.run_all` |
| 3. Test-time compute, offline (Steps 1–3, 5–6) | CPU (laptop) | `python -m task3_ttc.{data,grading,offline,signals,adaptive,summarize}` |
| 3. Test-time compute, live (Step 4) | Colab, one T4 | `task3_ttc/atml-pa3-task3-colab.ipynb` → `python -m task3_ttc.live` |

## Setup

```bash
git clone <repo-url> && cd <repo>/assignment_03/ATML-PA3
python -m pip install -r requirements.txt      # torch from the platform image
```

GPU notebooks need two secrets (Kaggle: *Add-ons → Secrets*; Colab: key icon):

* `HF_TOKEN` — Hugging Face token with write access. Checkpoints, logs and results are mirrored to
  a private model repo `<hf-user>/atml-pa3-store` (override with `PA3_STORE_REPO`) so sessions can resume.
* `GITHUB_TOKEN` — read access to this repository while it is private.

Every notebook is idempotent: run it, and when the session ends run it again. Finished jobs are
skipped and training resumes from the latest recovery checkpoint. Use `MODE = "smoke"` first.
On Kaggle the repository and checkpoints live in `/tmp` (the 20 GB `/kaggle/working` only receives
the results zip); use *Save Version → Save & Run All* to run headless for up to 12 h.

## Task 1 — what runs

`run_all` schedules: `data` → five `train_*` jobs (two at a time on T4 ×2) → seven `eval_*` jobs
→ `diagnostics`, `qualitative` → `summarize`.

* **Data** (`results/task1/data/`): first 40,000 eligible MetaMathQA rows in source order
  (revision `aa4f34d3…`); exclusion counts in `train_selection_stats.json`; probe IDs in `probe_ids.json`.
* **Training**: exact recipe from the handout. FP32 master weights for Full FT variants, frozen FP16
  backbone with FP32 adapters otherwise. Loss normalised by the response tokens of the whole effective batch.
  Logs: `results/task1/train/<variant>/log.jsonl` (loss, LR, grad norm, loss scale, skipped updates,
  Ω/λΩ/total for L2-SP), `summary.json` (time, peak memory, parameters, checkpoint sizes, displacement, overheads).
* **Evaluation**: lm-evaluation-harness 0.4.13 (`gsm8k_cot`, `hellaswag`, `boolq`, `arc_easy`),
  zero-shot, FP16. Per-example outputs in `results/task1/eval/<condition>/samples_*.jsonl`.
* **Diagnostics**: `results/task1/diagnostics/` (ρ_k, η, R(z) per prompt and summaries).
* **Qualitative**: `results/task1/qualitative/` (168 responses, automatic flags,
  `annotation_sheet_42.csv` for manual annotation).

## Task 2 — what runs

`data_build` (CPU, already run; outputs committed in `results/task2/data/`) → `features`
(downloads only the ~11k selected COCO images and caches SigLIP features) → `train` (three stages,
resumable every 250 updates, development evaluation on the prescribed schedule) → `evaluate`
(four image conditions on both final-test suites, pair bootstrap) → `summarize`.

## Task 3 — what runs

Supplied rollouts: [ATML-PA3-Data](https://drive.google.com/drive/folders/1utX-Gfi9vvaoi1mi0pzNpDGL1o1fAh23)
(downloaded with `gdown`). `data` verifies token-list alignment and writes the fixed splits
(`results/task3/splits.json`); `grading` fixes answer groups and correctness labels before any
analysis (`results/task3/grader.json`, `grades_*.parquet`); `offline` evaluates every rule for
N ∈ {1,2,4,8,16,32} over ten seeded orders; `signals` covers Step 3; `adaptive` covers Step 5, with
thresholds chosen on the development split only; `live` covers Step 4.

## Implementation choices to be aware of

These are interpretations where the handout leaves room; they are recorded here and in the code.

* T1: GSM8K overlap uses NFKC + lowercase + whitespace-collapsed exact match. The truncation flag is
  "response re-tokenises to ≥ 1,024 tokens". L2-SP's reference θ₀ is stored in bf16, the released
  checkpoint's own dtype, so it is exact; its gradient λ(θ−θ₀) is added once per optimizer update
  after unscaling. Skipped (overflow) updates still advance the LR schedule and are logged.
* T1: LoRA/OPLoRA use an in-repo implementation (`task1_finetune/adapters.py`, PEFT-style init: Kaiming-uniform A,
  zero B) so LoRA-16 and OPLoRA-16 start from identical factors (seeded).
* T2: visual tokens are wrapped in Qwen's `<|vision_start|>`/`<|vision_end|>` tokens inside the user turn.
  No-image inputs drop that whole block. The caption instruction is `"Describe this image in one sentence."`.
  A new AdamW optimizer is created at each stage. The connector output scale is calibrated on training
  data (rule in `results/task2/train/connector_calibration.json`). Answer NLL excludes the end-of-turn
  token; caption loss uses the training objective.
* T3: MATH answers are grouped with math-verify (`$answer$` parsing; first equivalent group). MathVista
  uses the official normalisation with option letters. Numeric normalisation failures keep a raw-string
  group (graded incorrect). Questions whose math-verify grouping exceeded the time/memory guard fall back
  to exact-string grouping (`grader_fallback` column; count in `grader.json`).
